# 原生验证与经验闭环（0.2.0）

补充 validation-handoff.md，不替代原有 COM、配置及 STEP 检验。来源：用户提供 skill-v3 的 native-modeling、task-card、blind-protocol、retrospective-workflow 及 E13/E14。当前版本只集成通用流程；课程专用固定28题脚本未直接移植。

## 执行及证据门槛

1. 记录 SolidWorks 版本、类型库、模板、单位、任务目录、活动文档、配置及权限；同一实例只允许一个写者，其他工作者仅做离线分析。新 API 先小试件。
2. 基线：原生文件副本、关键功能尺寸、配置、实体/组件数、特征错误警告、包络、必要接触/间隙及视图。
3. 试改：针对主要设计参数（圆角、避空、孔位、定位等）选择合理范围，记录原值、试改值、单位、预期及实测几何响应、重建与错误；不能仅凭任意厚度变化判定可编辑。
4. 恢复：finally 或等效机制恢复原式、值与配置，重新获取 COM 引用，重建并测量；失败保留日志，从检查点恢复，不覆盖原始输入。
5. 保存与重开：记录保存返回、错误和警告；关闭本任务文档及必要引用，再从磁盘重开核对特征、参数、组件路径和几何。不得关闭用户无关未保存文档。
6. 独立检查：必要 STEP 回读检查有效性、交叠、必要接触和包络；空交集与内核异常分别记录，不混用不同内核量测基线。数值容差不等于制造公差。
7. 交付真实原生视图、风险部位视图、源脚本、日志、参数及来源表；记录 PASS/FAIL/NOT_RUN/NOT_APPLICABLE 及原因。若工程验证不完整，列出未关闭项。

每项 edit_tests 记录 parameter、unit、configuration、key_design、before、changed、restored、expected_response、observed_response、response_verified、log。另记录 feature_errors_checked、save_evidence、reopen_evidence、native_reopen、native_edit_test、key_design_edit_test、restored 及总体状态。真实日志是依据，布尔字段不是验证本身。多项关键改动逐项覆盖；拓扑数量只能由生成器改变时说明边界。

## 批量任务与盲测（可选）

开工冻结 Skill 版本、完整任务 ID 清单、输入角色及评价规则。混合压缩包只提取确认的原始附件，避免全文检索、预览答案或让其他代理代读。任务 ID 由本轮预先定义，不继承课程固定清单。记录接触史和访问顺序。初稿目录保存 brief/design/explanation、validation、native、views、构建脚本与日志。全部题完成且工程证据审核后对初稿、脚本、知识索引和清单计算 SHA-256；保存独立冻结清单，比较前后复核。冻结失败不进入答案比较。答案和修订保存在独立目录，不覆盖初稿。发现污染如实标明受影响题，不能换代理恢复独立性。哈希只能检查变化，不是权限隔离或正确性认证。

评价维度：问题识别、功能接口、工艺与装配权衡、原生编辑及证据充分性。分类为核心思路一致、部分一致需修订、合理替代待条件确认、偏离遗漏、证据不足。不是官方成绩；参考答案也可有矛盾或缺失。

复盘记录：触发条件、原始证据、实际失败（若有）、采取行动、验证结果、适用边界、未关闭项、Skill 规则修改及版本。几何修订须重新实测；区分文档修订、保留初稿和未关闭问题。新一轮用未见案例；要声称提升需同条件基线、固定评价规则和实际结果。用户提供的28题及反馈属于历史训练/回归证据，不是本版本独立测试。
